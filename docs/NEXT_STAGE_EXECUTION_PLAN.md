# Common Room 用户需求、产品问题与下一阶段执行方案

版本：v0.1 · 2026-09-19

适用对象：项目作者、产品负责人、开发与运营协作者。

本文汇总当前讨论，并作为下一阶段范围与执行顺序的主要文档。原始分析与更多论据见[产品迭代与早期运营分析](PRODUCT_AND_OPERATIONS_STRATEGY.md)，现有实现见[架构说明](ARCHITECTURE.md)。文中新增功能均为拟执行方案，尚未开发或部署；作者服务容量、技术选型与实际排期仍需明确。

## 一、当前处于什么阶段

**下一阶段的目标，是让第一批真实用户完成一次有收获的使用，保存自己的学习内容，并有理由回来继续。**

项目已经有鲜明的空间氛围和艺术史内容，可以浏览作品、查看时代与画家、收藏、复习、写作以及发起问答。接下来需要把这些功能组织成连续的使用过程，并建立作者能够持续运营的工作方式。

| 已掌握的信息 | 依据与边界 |
| --- | --- |
| 有 Vercel 站点，目前尚无人使用 | 用户补充；尚未取得具体网址进行独立线上核验 |
| 作者可以投入较多时间 | 用户补充；每周具体投入和服务容量尚未确定 |
| 作者可能愿意回应用户提交的观察或练习 | 用户表示“我觉得是愿意的”；先作为设计前提，仍需与作者确认具体范围 |
| 评论区有试用兴趣和一些明确学习诉求 | 来自用户提供的贴文与评论摘录，尚无站内使用、留存或支付证据 |
| 现有代码含 6 个时代、22 件馆藏、17 位画家及 34 条画家作品笔记 | 仓库代码核对；馆藏与画家笔记存在重叠，数量不能相加作为独立作品总数 |
| 本地主要交互能够运行 | 此前已验证地图、收藏、复习揭晓、写作规则评分及问答回退；不代表真实 AI 或线上体验已经验收 |

本文使用三种证据标记：**直接需求**指评论者明确表达；**场景线索**指身份或情境提示了可能的任务；**产品假设**指我们提出、需要试用验证的解决方案。

“共 92 条评论”不能直接当作 92 位独立用户。材料包含作者回复和未展开的对话，也不构成有代表性的市场样本。作者询问的“建立审美体系”等选项，只有在评论者实际确认后，才能转为用户需求证据。

## 二、已经发现的用户需求

### 2.1 评论中的需求与使用线索

以下摘录均来自用户提供的材料，省略评论者昵称、位置与个人标识。

| 编号 | 用户需求或线索 | 评论依据 | 我们的理解 | 下一步怎样验证 |
| --- | --- | --- | --- | --- |
| N01 | 建立艺术史知识之间的联系 | “知识很零碎，形成不了一个完整的知识体系” | 用户希望知道作品、画家与时代之间怎样关联 | 让用户完成一条作品比较路线，观察能否说出关联 |
| N02 | 能够自己看懂作品 | “想系统了解学习艺术史，能靠自己大概看懂一些画作” | 用户想获得可以迁移的观察与理解方法 | 学完后换一件未讲过的作品，观察其能否提出具体证据 |
| N03 | 用时间轴建立年代关系 | “时间轴太有用了，求链接” | 时间轴可以作为首次使用入口 | 观察用户是否能借助时间轴找到关系，并进入作品进一步学习 |
| N04 | 顺利拿到入口并开始使用 | 多人“求链接”“申请试用”，有人问“怎么下载” | 必须明确这是网页、从哪里打开以及如何开始 | 请首次用户从真实分享入口独立进入，记录卡点 |
| N05 | 轻松逛展、接近艺术 | “喜欢逛美术馆和博物馆”“平时习惯逛展” | 存在自由探索与看展相关场景，未必想完成课程 | 询问最近一次看展经历，观察实际探索与回访行为 |
| N06 | 为课程学习或教学提供帮助 | 有人自述为 A-level 艺术史学生，另有人辅助教学 | 是明确的课程场景线索，尚不清楚具体作业、题型与难点 | 带着真实题目访谈学生与教师，确认考试局和课程范围 |
| N07 | 为工作补足艺术知识 | “在画廊工作但是没有专业艺术知识” | 可能存在介绍作品、理解展览或准备表达的任务 | 请对方展示最近一次工作困难，不直接推导机构采购需求 |
| N08 | 在有吸引力的空间中学习 | “版面设计很漂亮”“情境营造体验”“看着很好玩” | 氛围具有吸引力，是否促进学习与回访尚待验证 | 保留审美体验，观察用户进入后实际做了什么 |
| N09 | 参与试用和提供意见 | 有人表示愿意“认真给予反馈” | 可以邀请成为早期共创参与者 | 观察真实操作，同时回访没有开始或没有完成的人 |

N01—N04 有直接诉求依据；N05—N09 包含场景、偏好和参与意愿。专业身份、申请试用和视觉赞美都不能单独证明高频使用或支付意愿。

### 2.2 为满足需求而提出的产品假设

| 假设 | 为什么值得做 | 需要观察的结果 |
| --- | --- | --- |
| 一条短而完整的学习路线比大量入口更容易帮助初次学习 | 对应 N01、N02、N04 | 用户能独立完成观察与表达，知道下一步做什么 |
| 个人书房能支持持续学习 | 收藏、笔记和草稿需要接续，当前保存能力不足 | 用户回来找自己的内容并继续使用 |
| 可选账号与同步值得进入首版 | 长期记录与人工回应需要稳定归属 | 用户能保留游客内容、换设备继续，登录不会丢失原稿 |
| 作者的具体回应能帮助用户继续观察和修改 | 与作者的 common room 愿景一致，且用户判断作者愿意投入 | 用户收到回应后回来阅读或修改，作者工作量可承担 |
| 每周主题能连接内容传播和站内使用 | 可以复用作者的一份策展内容 | 用户从主题内容进入对应体验，并因下一次内容或回应回来 |

这些是待验证的方案，不能写成“评论者普遍要求账号、社区或人工批改”。

## 三、现在的产品问题

以下区分已经核对的能力缺口、设计判断与待验证项。没有线上用户数据，尚不能判定哪一个问题造成了实际流失。

| 编号 | 问题 | 当前依据 | 对使用或运营的影响 | 本阶段处理方向 |
| --- | --- | --- | --- | --- |
| P01 | 进入方式与首次使用任务不够明确 | 评论中有人问怎么下载；页面有多个房间与功能，但没有完整入门路线 | 初次用户可能不知道先做什么；影响程度待试用观察 | 明确网页入口、推荐一个起步主题，保留自由探索 |
| P02 | 内容展示与学习结果之间缺少连续引导 | 有作品笔记、时间轴和复习，但尚未组织完整的观察、表达、反馈和继续过程 | 用户看过信息后，未必知道如何形成自己的理解 | 先完成一条由作者审校的短路线 |
| P03 | 个人内容不能完整保存 | localStorage 只保存收藏 ID、语言和密度；写作草稿与聊天记录未持久保存 | 用户投入的文字可能丢失，难以接续学习 | 保存观察、草稿与进度，显示真实保存状态 |
| P04 | 没有账号与跨设备同步 | 当前没有身份与用户数据服务 | 长期记录和作者回应缺乏可恢复的个人归属 | 可选登录、云端保存、游客记录合并 |
| P05 | 缺少统一的个人学习入口 | 收藏、练习与作品散布在页面区域中 | 回来时难以找到上次内容 | 建立“我的书房”：继续上次、收藏、观察、练习与回应 |
| P06 | 尚无人工回应流程 | 没有提交版本、回应记录或作者工作台 | 作者愿意投入也难以形成稳定服务 | 建立主动提交、作者回复、用户修改的完整流程 |
| P07 | 写作评分不足以支持专业评阅承诺 | `scoreEssayResponse()` 依赖字数、术语和规则匹配 | 数值分数可能被误解为专业写作水平或考试分数 | 明确练习反馈性质，调整或暂不展示数值；专业评分另行校准 |
| P08 | 真实 AI 的可用性与服务边界未验收 | 有服务端接口和本地回退；尚未完成真实连接验证；代码未含用户限额 | 无法据此承诺持续 AI 服务或稳定费用 | 验证真实调用、区分回答来源，设置服务端用量控制 |
| P09 | 缺少可执行的用户运营记录 | 仓库未见产品行为埋点、反馈工作台和联系许可管理；是否有平台侧统计未知 | 作者难以分清进入、使用、回访与未完成原因 | 最小事件记录、反馈状态和自愿参与者名单 |
| P10 | 分享链接难以恢复具体学习位置 | 作品选择主要在内存中，尚无完整的作品/路线分享状态 | 贴文中的作品不容易被准确承接 | 首个主题及相关作品提供稳定直达链接 |
| P11 | 语言覆盖与内容范围需要准确表达 | 中文覆盖不完整，法文主要覆盖界面；内容偏重欧洲传统 | 宣传可能超过用户实际得到的体验 | 首条中文路径做完整，说明其他语言与内容覆盖范围 |
| P12 | 目标环境与缓存升级仍需验证 | 图片依赖外部源；现有 Worker 缓存同源 GET；手机与线上升级未完整验收 | 可能影响图片观看、更新和新增私人数据的正确处理 | 实测目标设备与网络；新增个人接口不得进入公共离线缓存 |

专业课程是后续潜力方向，但目前不能宣称完整覆盖。作为参照，Pearson Edexcel 的艺术史课程强调视觉分析、主题与时期及以证据支持论证，现有规则评分尚不能替代这种要求。具体课程匹配还应先确认作者采用的考试局与版本。[Pearson 官方课程规范](https://qualifications.pearson.com/content/dam/pdf/A%20Level/history-of-art/2017/specification-and-sample-assessments/specification-and-sample-assessments-GCE-HISOFART-SPEC.pdf)

## 四、下一阶段的执行战略

### 4.1 优先服务的人

**已经对艺术感兴趣，希望把零碎知识连接起来，并能够自己观察、理解和表达的人。**

这是一种任务划分，可能包括看展爱好者、学生和艺术从业者。选择这一群体，是因为其明确诉求与现有内容接近，容易通过真实任务观察成效；尚未证明他们是最大的市场。

自由探索者继续可以轻松逛。A-level 学生和教师作为早期访谈与专业共创对象，先确认具体任务，暂不将全课程备考设为首版交付目标。

### 4.2 希望交付的用户结果

首次使用后，用户能够围绕一件作品留下自己的观察，并给出至少一个具体依据。再次使用时，能找到这段内容，继续比较、修改或学习相关作品。

愿意深入交流的人可以主动提交给作者。作者围绕具体内容给出回应，帮助用户继续思考。学习价值应通过实际表达与修改观察，不能由“点击完成”或注册数替代。

### 4.3 产品与运营的主线

> 主题内容或分享入口 → 游客直接体验 → 观察与表达 → 保存到个人书房 → 自愿请求作者回应 → 回来阅读和修改 → 继续相关主题。

这一主线保留三种体验：自由浏览、自助学习、作者参与的有限回应。用户可以选择深度，不要求所有访客都写作或提交。

账号进入首版，采用可选登录。它服务于云端保存、跨设备继续与人工回应，不在首页阻挡第一次体验。

### 4.4 本阶段的投入边界

先复用现有作品，做好一个完整中文主题与一套可持续的回应流程。作品素材数量、语言数量和页面数量不作为本阶段成绩。

暂缓完整三语内容、原生 App、开放论坛、即时私聊、多教师分配、积分等级、全课程自动判分及付费订阅系统。是否推进，由第一轮实际任务、回访与作者工作量决定。

### 5.1 登录与保存规则

| 行为 | 游客 | 登录用户 |
| --- | --- | --- |
| 浏览作品、地图和学习路线 | 直接使用 | 直接使用 |
| 收藏、观察与写作草稿 | 保存在当前浏览器，明确保存范围 | 保存到账号，并显示同步结果 |
| 换设备继续 | 不承诺恢复 | 登录后恢复自己的记录 |
| 请求作者回应 | 可先写内容，在最终提交前登录 | 预览并确认本次提交 |
| 查看历史回应 | 登录后找回 | 在书房中查看 |

需要一起实现的细节：登录失败不丢草稿；已有账号可以合并游客收藏；冲突草稿保留可辨认的版本，不静默覆盖；同步失败不得显示“已同步”；退出后不暴露上一账号的私人内容。

账号注册、人工回应通知和运营订阅分别表达用途。默认不因注册账号自动加入营销消息名单。登录方式及供应商需在目标用户设备、邮箱与网络条件下验证后确定。

### 5.2 作者回应规则

**用户操作：** 写观察或练习 → 选择希望得到的帮助 → 登录 → 预览提交 → 确认提交 → 查看回应 → 保存修改。

**作者操作：** 查看列表 → 阅读相关作品及提交版本 → 撰写并预览回复 → 明确发送 → 根据实际处理量调整接收容量。

首版建议如下，具体范围与服务安排需作者确认：

- 围绕站内作品的一段观察或短练习回应；不默认提供整篇论文修改或正式考试判分。
- 每位用户同一时间保留一份待回应请求；作者设置每批接收量及开放状态。
- 提交保存固定版本。作者只能看到用户主动提交的内容，用户之后修改私人草稿不会自动共享。
- 基本状态为待回应、已回应、已完成；待回应可撤回，超范围可说明原因后结束。
- “已完成”由用户明确结束本次交流，或在说明原因后关闭；打开页面、读过回复或保存修改不自动等同于完成学习。
- 作者回复可以指出一处具体观察、一个需要补充依据的判断，以及下一步可尝试的问题。
- 站内展示回应；邮件等服务提醒为可选项。首版不承诺即时回复或无限追问。

达到容量时暂停新请求，已有私人草稿仍可保存。作者是否愿意回应已经有正向讨论基础，但具体时限不能在作者确认前写成对外承诺。

## 六、执行步骤、负责角色与完成条件

以下是依赖顺序，不是固定工期。角色可以由同一个人兼任，进入开发排期时再明确实际负责人。内容准备、用户访谈和技术可行性检查可同时进行，后续发布依赖完整验收。

| 步骤 | 主要动作 | 负责角色 | 交付物 | 完成条件 |
| --- | --- | --- | --- | --- |
| 1. 明确试用与服务范围 | 核对站点、目标任务和首个主题；与作者确认接收内容、容量及回应安排；了解少量真实学习任务 | 作者、产品负责人 | 一页试用说明、首条路线稿、服务范围表、已知问题清单 | 用户承诺与作者可交付范围一致，未知事项明确 |
| 2. 核对体验与技术方案 | 实测目标手机/网络、图片与 AI；设计游客转账号、保存状态、提交与回复页面；选择身份/数据服务 | 工程、产品负责人 | 页面流程、数据与权限设计、技术选择依据、验证记录 | 登录与数据隔离可实现，主要入口可用，关键成本与服务限制明确 |
| 3. 完成个人学习基础 | 稳定作品 ID 与直达链接；开发保存、书房、账号与同步；接入最小事件；作者完善中文路线 | 工程、作者 | 可体验的路线、书房与账号版本 | 游客能完成并保存；登录后内容保留；换设备能恢复 |
| 4. 完成作者回应 | 开发提交固定版本、状态、回复、用户修改和作者工作台，接入容量与暂停功能 | 工程、作者 | 从提交到后续修改的完整流程 | 普通用户与作者分别走通流程，权限和异常情况通过检查 |
| 5. 验收并准备小范围试用 | 在独立预览/测试环境验证；作者审校内容和反馈文案；记录发布版本及恢复方式，再发布首个试用版本 | 工程、作者、产品负责人 | 验收记录、发布版本、试用入口与反馈通道 | 本文验收清单通过后再邀请，不将页面能打开当作全部完成 |
| 6. 招募第一批并实际运营 | 作者邀请自愿参与者；跟踪进入与完成；处理提交；回访未打开、未完成和再次使用的人 | 作者、运营角色 | 每位参与者的任务与使用记录、回应记录、问题清单 | 能说清每个阶段人数和真实原因，完成一次后续观察 |
| 7. 依据结果选择下一步 | 复盘学习表达、回访、登录阻力、作者工作量；选一个最值得继续的方向 | 作者、产品负责人 | 复盘结论、下一批任务及取舍 | 每项新增投入有行为或内容证据支持 |

工程原则：沿用当前可用的页面与 Vercel 托管基础，按需要增加身份、数据和服务端权限。内容、保存与身份、提交与回应逐步分开维护；不把全面重写前端设为启动运营的前提。新增个人数据接口及认证回调应与现有离线缓存分离。

### 开发后的验收清单

- [ ] 从实际分享入口打开首个主题，手机上图片、文字与操作正常。
- [ ] 无需登录即可完成观察与表达，刷新后仍能找到本机草稿。
- [ ] 登录失败、刷新页面或网络暂时中断不会清空已写内容；同步状态准确。
- [ ] 游客记录能进入新账号，也能与已有账号合并；冲突草稿没有被静默覆盖。
- [ ] 第二台设备登录后能继续；退出后不向下一位使用者展示私人内容。
- [ ] 用户 A 不能读取或修改用户 B 的笔记、提交或回复；普通账号不能访问作者后台。
- [ ] 只有用户主动提交的固定版本向作者开放，私人草稿保持私密。
- [ ] 作者能保存回复草稿、预览并发送；用户能找到回应并保存自己的修改。
- [ ] 重复点击提交不会生成多份请求；撤回和暂停接收时不会丢失私人草稿。
- [ ] AI、本地笔记、规则反馈和作者回复来源可区分，实际服务与对外说明一致。
- [ ] 站点更新与退出登录后，Service Worker 不返回过期的私人数据。
- [ ] 运营记录能区分访问、使用、提交、回应与回访，排除内部测试数据。

## 七、第一轮怎样运营与复盘

### 7.1 围绕同一个主题组织内容

作者选择一个值得观察的问题，将其用于小红书内容、站内路线和后续回应。比如围绕两件现有作品提出“人物与观看者是什么关系”，具体艺术史解释由作者审校。

帖子提供一个可理解的问题和清楚的试用办法；网站直接承接同一主题；用户保存或提交自己的观察；作者回应，再给出下一件可以比较的作品。平台具体链接与私信方式按账号实际可用能力确定，本文不预设已开通的导流功能。

邀请时说明试用内容、预计投入以及人工回应范围。可以先准备约 10 位目标明确、自愿参与的试用者，实际人数依据作者容量调整。这是试验规模建议，不是当前用户数或市场测算。

### 7.2 每次复盘应回答的问题

| 阶段 | 记录什么 | 可以判断什么 |
| --- | --- | --- |
| 申请与送达 | 同意试用人数、收到入口人数 | 招募与入口交付是否完成 |
| 实际进入 | 实际访问人数、来源主题、设备及错误 | 有没有打开，是否遇到环境问题 |
| 第一次使用 | 开始路线、保存观察、独立完成的人数 | 任务是否清楚，能否获得第一次结果 |
| 账号与同步 | 发起登录、完成登录、迁移成功及失败原因 | 登录是否承接了保存需求，是否造成额外阻力 |
| 作者回应 | 提交、有效请求、已回复、等待状态、作者投入时间 | 服务是否能交付，工作量是否可持续 |
| 回来继续 | 后续一周回来阅读、修改或学习新作品的人数 | 用户回来为了什么，有无继续学习行为 |
| 学习与满意度 | 经许可抽看前后表达、访谈具体收获与未解决问题 | 是否更会观察和表达，而非只完成按钮操作 |

匿名浏览器标识与登录账号分别记录，不能直接相加当作独立人数。注册人数不代表联系许可；回复页面打开不代表理解；一次保存也不证明掌握。分析事件默认记录动作、内容编号和版本，不收集私人笔记全文。

自然回访、统一主题提醒、作者单独催回，以及收到人工回应后的回访需要区分。人工服务带来的效果可以是产品价值，但不能直接声称为自助学习工具的留存效果。

### 7.3 根据证据怎样调整

| 观察到的情况 | 优先行动 |
| --- | --- |
| 愿意试用，但没有打开 | 检查入口送达、打开方式和时间情境，再决定是否调整宣传 |
| 打开后没有开始 | 观察首页、作品加载和任务说明，减少不必要选择 |
| 开始了但没有完成 | 检查任务长度、理解门槛、保存问题与内容适配 |
| 登录或同步处失败 | 优先修复这条路径，保留游客原稿，不增加更多获客投入 |
| 收藏和自由探索持续，但少有人愿意写 | 调整主入口和评价方式，验证策展与看展需求 |
| 收到作者回应后回来修改 | 继续改善回应质量，核对作者工作量，再扩大接收量 |
| 只有逐人催促才继续 | 验证是否更适合有限规模的主持型活动，不能归因于自助产品已成立 |
| 学生持续提交具体题目，教师愿意参与 | 选一个明确课程单元做专项验证，再扩展专业服务 |

第一轮样本很小，优先保留人数、行为经过与具体表达；不根据少量评论或几次回访推算市场规模、稳定留存率或收入。

## 八、开始执行前需要明确的事项

| 事项 | 当前状态 | 由谁落实 |
| --- | --- | --- |
| 现有站点地址、部署版本和目标访问环境 | 已知有站点，尚未独立核验 | 作者提供信息，工程实测 |
| 第一批参与者的主要任务 | 有评论线索，尚未访谈确认 | 作者、产品负责人 |
| 首条主题、作品与中文导览内容 | 有选题建议，尚未完成教学审校 | 作者 |
| 人工回应接收范围、每批容量、预计安排 | 用户判断作者愿意，具体承诺未定 | 作者 |
| 登录方式、数据服务、通知渠道及可承担成本 | 尚未选定，不因已有 Vercel 站点自动确定 | 工程提出可行方案，项目负责人选择 |
| 首次试用的具体负责人及时间 | 只有执行顺序，没有承诺日期 | 项目负责人协调 |

这些待定项不妨碍整理需求、设计页面和准备内容。涉及服务承诺、数据服务配置与公开发布的具体安排，应在对应步骤落实后执行。

**本阶段完成的标志：第一批用户能够顺利进入、保存并继续自己的学习；主动提交的人能获得作者回应；作者能够根据真实记录决定接下来改什么。**
